# Cursor vs Windsurf

Comparison for sellers when accounts evaluate "AI IDEs" broadly.

## One-line positioning

Both are AI-native IDE experiences. Differentiation for enterprise sellers should be grounded in **buyer-specific** evaluation criteria — not generic feature checklists.

## Comparison framework (validate per account)

| Dimension | Questions to ask | Cursor angle |
|-----------|------------------|--------------|
| Codebase indexing | How large is the monorepo? | Emphasize repo-wide context |
| Enterprise controls | SSO, privacy mode, audit needs? | Align to security narrative |
| Agent reliability | Multi-file change success rate? | Propose structured pilot |
| Vendor stability | Long-term support concerns? | Use sourced company facts only |
| Existing footprint | Copilot + JetBrains + VS Code mix? | Meet devs where they work |

## Seller caution

The AI IDE market moves fast. **Do not recite stale feature matrices in customer meetings.** Use this doc as internal prep; validate current capabilities in SE-led technical discovery.

## Competitive deal strategy

1. Identify champion persona (staff engineer, DX lead)
2. Run structured 2-week pilot on real repo slice
3. Measure: time-to-PR, review comments, developer NPS (buyer's own data)
4. Never invent benchmark results — use customer's pilot data only

## When Windsurf is mentioned

Ask: "What prompted the comparison?" Often reveals real pain (speed, context, price, policy) you can address without negative selling.
